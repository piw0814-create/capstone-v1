## 노션 원문 대비 보완 사항

노션의 설명에는 작업별 `pending → in_progress → completed` 상태와 하위 에이전트의 토큰을 표시하도록 되어 있으나, 제공 코드는 완료 상태만 반환하여 작업 시작 이벤트와 하위 토큰이 화면에 전달되지 않았다. 설명된 UX를 구현하기 위해 다음을 보완했다.

1. **작업 시작 단계 분리**: Supervisor graph에 `start_task` 노드를 추가하여 실제 작업 실행 전에 `in_progress` 상태를 별도 업데이트로 반환하도록 했다. 변환기는 이를 `task_started`로 전달한다.
2. **하위 토큰 전달 연결**: 하위 에이전트를 `astream`으로 실행해 실제 생성 토큰을 읽고, `get_stream_writer()`로 작업 ID를 포함한 custom 이벤트를 상위 그래프에 전달했다. 이를 외부 SSE의 기존 `sub_agent_token` 이벤트로 변환한다.
3. **작업 ID와 완료 처리**: 현재 작업 ID에 해당하는 토큰만 전달하고 작업 완료 시 활성 ID를 해제한다. 계획 텍스트와 원시 도구 응답이 작업 토큰으로 잘못 표시되지 않게 했다.
4. **기존 토큰 중복 수정 유지**: React 개발 모드에서 같은 토큰과 도구 박스가 중복 표시되던 문제는, 기존 상태를 직접 수정하지 않고 새 객체·배열로 갱신하도록 보완한 코드를 유지했다.

작업의 순차 실행, Research/Writing의 역할·모델·MCP 도구, 최종 답변 전체를 `token` 이벤트 한 번으로 보내는 원문의 간단화는 유지했다.

### 보완 검증

별도 실제 SSE 검사에서 `task_started` 3회, `sub_agent_token` 712회, `task_completed` 3회, 최종 `token` 1회, `done` 1회를 확인했다. 각 작업의 시작 → 해당 ID의 토큰 → 완료 순서와, 마지막 Writing 토큰을 이어 붙인 문자열이 최종 답변과 정확히 같은지 검사해 통과했다.

supplement-progress.png는 같은 F1 질문으로 보완 기능을 확인한 별도 실행(Thread: 7e2d7909)의 실제 화면이다. 노란 진행 카드 안에 실제 생성 중인 텍스트가 표시되는 모습을 담았으며 F1-multi.png의 완료 화면과는 실행 ID가 다르다.

캡처는 실제 Chrome 화면을 사용했고 JPEG 원본을 내용 변경 없이 PNG로 변환했다. 이 결과는 실제 실행에서 관찰한 기능과 화면을 기록한 것이며, 생성된 장애 대응 내용 전체의 사실 정확성을 별도로 검증했다는 의미는 아니다.
